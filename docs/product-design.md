## 1. 产品概述

### 1.1 一句话定位

**帮懒人情侣/个人记录每一天的 App —— 拍张照，AI 帮你写日记，沉淀成时间线。**

### 1.2 要解决的问题

- 情侣想记录在一起的点点滴滴，但**写日记/手账太累**，坚持不下来。
- 现有日记类产品依赖用户主动长篇书写，**输入成本过高**，新鲜感过后就废弃。
- 现有相册类产品只存照片，**没有"事件"和"故事"的沉淀**。

### 1.3 核心价值主张

| 价值 | 说明 |
|---|---|
| **极低输入成本** | 拍一张照（或一句话）即完成一次记录，其余交给 AI |
| **AI 补齐上下文** | 时间 + 定位 + 照片内容 + 历史记忆 → 自动生成有温度的日记 |
| **双人共享** | 两个人的记录沉淀进同一份时间线，是"我们的"而不是"我的" |
| **个人可用** | 没有另一半也能用：单人空间 = 个人生活日记 |
| **数据私有** | 自部署，数据在自己服务器；AI 用自己的 key，按量付费 |

### 1.4 产品形态

- **最终形态：移动 App（Flutter 跨平台）**，Android 优先，iOS 后置。
- 开发与调试：同一套 Flutter 代码可跑 **Windows 桌面 / Chrome（Web）**，无需先装 Android 工具链即可开发验证。
- Android APK：用 **GitHub Actions CI 构建**（公共仓库免费），本机可不装 Android Studio。
- iOS：需要 Mac + Xcode，列为后续事项（D7）。

## 2. 目标用户与场景

### 2.1 用户画像

- 国内 20~35 岁情侣或单身个人，习惯拍照记录生活，但不愿意写长文。
- 至少一方愿意花 5 分钟配置一次 AI key（一次性成本）。
- 自部署/自托管爱好者，或愿意用 Docker 跑服务的人。

### 2.2 典型场景

| 场景 | 输入 | 输出 |
|---|---|---|
| 日常约会（吃饭、散步、看电影） | 一张牵手/合照 | 短记录：时间 + 地点 + 照片场景描述 |
| 旅行 | 多张风景/合照 + 一句话主题（"在洱海边看日出"） | 一段完整日记（扩写模式） |
| 纪念日（在一起 100 天、生日） | 照片 + "今天是我们 100 天" | 深情纪念日记，自动算出天数 |
| 补记（昨天忘了记） | 照片/文字 + 回填时间 | 按回填时间生成，归入时间线正确位置 |
| 个人记录（单人空间） | 一张照片/一句话 | 个人生活日志 |

### 2.3 明确不做（本阶段）

- 不做社交/广场/公开分享（隐私敏感）。
- 空间上限 **2 人**，不做多人/群组。
- 不做 AI 聊天陪伴。

## 3. 核心概念

| 概念 | 定义 |
|---|---|
| **User（用户）** | 一个账号（邮箱+密码），属于一个空间 |
| **Space（空间）** | 1~2 人的数据容器：时间线、日记、AI 配置、在一起日期。单人=个人日记，双人=情侣共享 |
| **Event（事件）** | 一次记录。一个事件 = 时间 + 地点（可选）+ 照片（0~9 张）+ 用户备注（可选）+ AI 正文 |
| **Diary（日记正文）** | 事件的可编辑正文，由 AI 生成、用户可改 |
| **Timeline（时间线）** | 空间内全部事件按时间排序的展示视图 |

**数据归属**：Event / Diary / 照片都属于 **Space**。双人模式下两个人看到的完全一致（共享同一份回忆）。

## 4. 功能需求

### 4.1 P0 · MVP（闭环必需）

#### F1 账号与空间（支持 1~2 人）
- 注册/登录：邮箱 + 密码（bcrypt 哈希）。
- 创建空间：注册后自动创建个人空间（**单人立即可用**，无需邀请）。
- 邀请第二人：空间内随时生成 6 位邀请码发给另一半；对方输入码加入（变为情侣模式）。
- 空间上限 **2 人**；创建者可**转让**空间。
- 已加入/已满时给出明确提示。

#### F2 记录事件（核心输入）
- 入口：首页底部大按钮「记录此刻」。
- 选照片：系统相册多选（≤9 张），客户端压缩后上传（长边 1600px，质量 0.8）。
- 采集时间：默认当前时间，**可回填修改**（支持补记）。
- 采集定位：App 系统定位；失败/拒绝时**降级**为手动输入地点或留空（不阻塞记录）。
- 反地理编码：可选配置高德 key 时，坐标 → 地名；无 key 时显示坐标或留空。
- 用户备注（可选）：一句话 / 主题 / 心情。不填则走"纯照片自动生成"模式。

#### F3 AI 生成日记
- 点击「生成日记」→ 后端调用多模态 LLM。
- 输出展示在编辑区，带「AI 生成」标记；用户可**编辑 / 重新生成 / 换文风**。
- 保存后事件进入时间线；未生成正文也可先保存（照片即记录）。

#### F4 时间线展示
- 按月分组、倒序时间轴；顶部显示「在一起第 N 天」（双人空间，由 start_date 计算）。
- 事件卡片：照片墙（点击查看大图）+ 正文 + 时间 + 地点 + 作者昵称。
- 空状态：引导第一次记录。

#### F5 设置
- AI 配置（**空间级共享**）：Base URL + API Key + 模型名 + 文风（见 §6.4）。
- **后端地址配置**（App 连接自部署后端）。
- 在一起日期（start_date）设置与修改。
- 个人信息：昵称、头像。
- 数据导出（见 F6）。

#### F6 数据导出
- 一键导出为 ZIP：全部事件 JSON（含正文、时间、地点）+ 全部照片文件。

### 4.2 P1 · 增强

- **地图视图**：事件坐标投影到地图（高德），看"去过的地方"。
- **纪念日列表**：自动识别（100 天、1 年…）+ 用户自定义纪念日。
- **照片 EXIF**：读取拍摄时间作为事件时间默认值（用 exifr）。
- **编辑历史**：保留 AI 原文，用户编辑后可回退。
- **搜索**：按正文/地点/备注关键字搜索事件。
- **通知提醒**：App 推送"该记录啦"（App 形态下可实现）。

### 4.3 P2 · 远期

- iOS 正式支持。
- 语音输入（口述一句话 → ASR → 备注）。
- 年度回顾报告（类网易云年度报告）。
- 分享卡片（生成一张图发朋友圈）。
- 微信小程序（复用后端 API）。

## 5. 核心流程

### 5.1 记录流程（正常路径）

```
[首页] 记录此刻
  → 选照片(≤9张, 客户端压缩)
  → 自动带出: 当前时间 / GPS定位(可选→反地理编码→地名)
  → 用户可改时间、改地点、填一句话备注(可选)
  → [生成日记]  → 后端组装上下文调 LLM → 返回正文(可编辑/重新生成/换文风)
  → [保存] → Event 入库 → 刷新时间线
```

### 5.2 AI 生成流程（后端）

```
请求: eventId
  → 读取 Event(时间/地点/备注) + 照片(压缩后 base64)
  → 可选: 读取最近 N 条日记摘要作为"历史记忆"
  → 组装 prompt(见 §6.2)
  → 调 LLM(多模态, OpenAI 兼容协议)
  → 返回正文 → 客户端展示
```

### 5.3 加入流程

```
A 注册 → 自动获得个人空间 → 记录/设置均可直接用
A 想拉另一半 → 生成邀请码(6位) → 发给 B
B 注册 → 输入邀请码 → 加入 → 空间变为 2 人(情侣模式)
```

## 6. AI 设计

### 6.1 能力来源：BYOK

- 用户在设置里填：`Base URL` + `API Key` + `模型名`。
- 统一走 **OpenAI 兼容协议**（`POST {base_url}/chat/completions`），兼容：
  - 通义千问（qwen-vl-max 等）
  - 智谱（glm-4v 等）
  - DeepSeek / Kimi（文本模型，照片能力弱，可选）
  - OpenAI（gpt-4o）
- 提供"模型推荐"预设列表（各厂商 base_url + 推荐多模态模型名），用户可自填任意兼容端点。

### 6.2 Prompt 策略

**System**（角色设定，核心约束）：
> 你是情侣日记助手。根据用户提供的照片、时间、地点、备注，写一段自然温暖的日记。要求：
> 1. 只描述照片中**可见的事实** + 提供的**时间/地点**；照片里没有的信息不得编造成事实。
> 2. 对心情/动机的推测必须用"大概 / 也许 / 好像"等不确定语气。
> 3. 有备注时围绕备注扩写；无备注时写 80~150 字短记录；有备注时可写 150~300 字。
> 4. 时间地点缺失时不要编造，跳过即可。

**User 消息**：时间、地点（或"地点未知"）、备注（或"无"）、照片（多模态）。

**历史记忆注入**（P1 起做）：将最近 5 条日记摘要 + "在一起天数"拼入上下文，让新日记有连续性。注：这些摘要会随请求发往第三方 API，属隐私权衡，在设置中说明。

### 6.3 幻觉控制

- Prompt 硬约束（见 §6.2）。
- 定位失败 → prompt 里明确写"地点未知"。
- 生成正文标注「AI 生成」，**全部可编辑**，鼓励用户改。
- 保存时记录 `is_ai_generated` 与 `edited_by_user` 标记。

### 6.4 文风（P0 提供 2 种，P1 扩展）

| 文风 | 描述 |
|---|---|
| 温暖日常（默认） | 自然、口语化、有温度 |
| 文艺 | 抒情、意象化 |
| 幽默 | 轻松、俏皮（P1） |
| 简洁 | 一句话记录（P1） |

文风为**空间级设置**，生成时可临时切换。

### 6.5 生成失败降级

- LLM 调用失败（无 key / 超时 / 限流）→ 提示错误，**不阻塞保存**（可先存照片，之后补生成）。
- 提供"重新生成"按钮。

## 7. 数据模型（草案）

```text
User
  id            PK
  email         UNIQUE
  password_hash
  nickname
  avatar_path
  created_at

Space
  id            PK
  invite_code   UNIQUE, 6位, 可随时重新生成
  start_date    date?      // 在一起日期(双人模式), 可改; 单人可为空
  created_by    FK User
  created_at

SpaceMember
  space_id      FK Space
  user_id       FK User
  role          'owner' | 'member'
  joined_at
  (UNIQUE space_id+user_id; 上限 2 人由业务层保证)

Event
  id            PK
  space_id      FK Space
  author_id     FK User
  happened_at   datetime  // 可回填
  lat / lng     nullable
  location_name nullable  // 反地理编码结果或手填
  note          nullable  // 用户备注/主题
  content       text      // 日记正文(AI生成或用户编辑)
  is_ai_generated  bool
  edited_by_user   bool
  created_at / updated_at

Photo
  id            PK
  event_id      FK Event
  file_path     // 本地存储路径
  created_at

AiConfig            // 空间级, 一张表一行
  space_id      FK Space, UNIQUE
  base_url
  api_key
  model
  style         // 文风
  updated_by / updated_at
```

## 8. 技术架构（D6/D7/D8）

### 8.1 总体形态

- **后端**：REST API 单体服务（Node/TS），SQLite 数据库，照片存本地文件系统。
- **客户端**：Flutter App（Android 优先），开发期可用 Windows 桌面 / Chrome 目标运行调试。
- **部署**：后端 Docker Compose（后期）；本地开发直接 `npm run dev` 直跑。
- **App 连接**：App 设置里配置后端地址（局域网 / 公网 / 内网穿透均可，见 §9.4）。

### 8.2 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 客户端 | **Flutter** | 一套代码 → Android/iOS/Web/桌面；开发期无需 Android Studio 即可在桌面/Web 调试；UI 表现力强 |
| 后端 | Node.js + TypeScript + Express + Prisma | 本机已装 Node 20；Prisma 对 SQLite 友好 |
| 数据库 | SQLite | 零配置，单文件，个人部署友好 |
| AI 客户端 | 自写 OpenAI 兼容 client（无重依赖） | 协议简单，避免 SDK 绑定 |
| 构建 | GitHub Actions（后端 Docker 镜像 + **Android APK**） | 公共仓库免费 CI，免装 Android Studio |
| 反地理编码 | 高德 Web 服务 API（可选配置 key，无 key 降级） | 国内地名准确 |

### 8.3 关键实现要点

- 客户端图片压缩（image_picker + 压缩库）：长边 1600px / 质量 0.8。
- 坐标：系统定位返回 WGS-84；高德用 GCJ-02，接入地图时需坐标转换（P1）。
- 多模态请求：照片转 base64 内联发送（控制单张 ≤ 1.5MB）。
- App 与后端通信：原生 App 可用 `http://IP:端口` 直连（自用场景可接受明文）；后续 Web/小程序才需 HTTPS + 域名 + 备案。
- 轻量云安全：只开放 App 用端口；SSH 用密钥登录；照片是核心资产，服务器需定期备份（数据盘/快照/定期 rsync）。

## 9. 隐私、安全与联网

| 项 | 方案 |
|---|---|
| 数据归属 | 全部数据在本部署实例内（DB + 照片目录），项目不收集任何数据 |
| AI 数据流向 | 照片与上下文会发送到**用户自配的** AI API；README 与设置页明示 |
| API Key 存储 | 明文存 SQLite（MVP）；README 警示风险；P1 做可选加密 |
| 密码 | bcrypt 哈希 |
| 邀请码 | 6 位随机，可重新生成 |
| 开源协议 | MIT |
| 合规提示 | 项目是工具，部署者自行负责个人信息保护（定位/照片属敏感信息）；README 给指引 |

### 9.4 App 联网方式（自部署现实路径）

| 方式 | 说明 | 适用 |
|---|---|---|
| **轻量云 IP 直连（推荐）** | App 填 `http://服务器IP:3000`；**无需域名、备案、HTTPS**（原生 App 不受浏览器 HTTPS 限制） | 两人异地同步，最省事 |
| 局域网直连 | 手机与后端同 Wi-Fi，App 填 `http://192.168.x.x:3000` | 家里自用，零成本 |
| 内网穿透 | frp / cloudflared | 无公网 IP 的折中 |
| 组网 | Tailscale / ZeroTier | 对个人友好，手机装客户端即可 |

> 域名 + 备案 + HTTPS 仅在需要 **Web 端 / 小程序** 时才强制（浏览器安全上下文限制）。当前 App 形态不需要。
